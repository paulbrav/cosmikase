# COSMIC configuration (chezmoi source notes — NOT applied)

chezmoi ignores every source entry whose name begins with `.` (except its own
`.chezmoi*` specials), so this file stays source-only and is never written to
`~/.config/cosmic/`. The applied files here (`autotile`, `active_hint`, the shortcuts
`custom`) carry their own inline citations where the format allows comments; this note
documents the parts that cannot (the bare-value atom files) and the overall design.

COSMIC (cosmic-comp, cosmic-settings-daemon) watches `~/.config/cosmic/` with inotify
and reloads live — there is no reload command.

## Storage model

`cosmic-config` stores a *versioned* config as `<component>/v<N>/` where **each struct
field is its own file** named after the key, holding a RON-serialized value. The
`CosmicConfigEntry` derive's `write_entry` calls `Config::set(key, value)` per field,
and `key_path(key)` appends the field name under
`~/.config/cosmic/<component>/v<N>/`, written atomically.
Source: <https://github.com/pop-os/libcosmic> (`cosmic-config`), verified 2026-07-16.

So enabling autotiling by hand = writing the single file
`com.system76.CosmicComp/v1/autotile` containing `true` (not a whole struct). An
external tool need only write the atoms it wants to change; missing atoms fall back to
each field's `Default`.

## com.system76.CosmicComp/v1  (files applied by this slice)

Config struct `CosmicCompConfig`:
<https://github.com/pop-os/cosmic-comp/blob/master/cosmic-comp-config/src/lib.rs>

| atom file     | value | meaning |
|---------------|-------|---------|
| `autotile`    | `true`| Automatic tiling on (pop-shell muscle memory). Struct default is `false`. |
| `active_hint` | `true`| Draw the focused-window indicator. (`true` is already the struct default; written to declare intent.) |

Deliberately NOT written (left at `Default`): `autotile_behavior` (`Global` — tile
everywhere, matching the old pop-shell feel), `focus_follows_cursor`,
`edge_snap_threshold`, input/xkb/workspace config, etc.

### GAP: the active-hint color is not a CosmicComp key

The audit wanted pop-shell's orange active hint `rgb(233,84,32)`. cosmic-comp exposes
no color key here — `active_hint` is only a boolean. The color comes from the COSMIC
theme: `active_window_hint()` uses `theme.window_hint` if set, else the theme `accent`.
Source: <https://github.com/pop-os/cosmic-comp> `src/theme.rs`, verified 2026-07-16.

So the orange belongs in the theme RON (`com.system76.CosmicTheme.Dark/v1/theme`, key
`window_hint`), owned by the themes slice — see the handoff note. Float encoding:
`window_hint: Some((red: 0.913725, green: 0.329412, blue: 0.125490, alpha: 1.0))`.

## com.system76.CosmicSettings.Shortcuts/v1/custom

Full schema citations live inline in `custom.tmpl`'s header comment (RON tolerates
`//` comments, so they ship with the file). Summary: RON map of `Binding -> Action`,
merged over `/usr/share/cosmic/.../defaults`, custom wins on duplicate bindings.
Sources: cosmic-settings-daemon `config/src/shortcuts/` (binding/action/modifier/sym),
`data/system_actions.ron`; cosmic-comp `data/keybindings.ron` (defaults) and
`src/input/actions.rs` (`Spawn` runs `/bin/sh -c`). Verified 2026-07-16.
